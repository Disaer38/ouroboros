### Доказанный механизм работы

guh123 работает по механизму **Negative Risk Arbitrage** с высокой частотой:

**Алгоритм:**
```
1. Мониторить orderbook 5m BTC/ETH рынков в режиме реального времени
2. Если P(Up) + P(Down) < 1.0 (neg-risk существует):
   - Купить Up @ P_up
   - Купить Down @ P_down
   - Locked profit = (1 - P_up - P_down) * min(size_up, size_down)
3. Держать до экспирации (0 SELL трейдов подтверждено)
4. Получить выплату от winning side
```

### Где guh123 берёт neg-risk?

В CLOB-маркете neg-risk возникает когда:
1. **Временны́е расхождения**: крупный ордер на одну сторону двигает цену, другая сторона ещё не отреагировала
2. **Market maker отсутствие**: в небольших 5m окнах меньше ликвидности
3. **Latency**: между обновлением orderbook и реакцией других трейдеров есть окно ~1-5 секунд

### Почему avg_sum ~ 1.01-1.03 в агрегате?

Потому что бот не всегда открывает **полные** neg-risk позиции:
- Иногда открывает только одну сторону (если другая слишком дорогая)
- Дополняет существующую позицию при движении цены
- Некоторые позиции — momentum следование (купил Up потому что BTC растёт)

## 🚀 Воспроизводство стратегии: Технические требования

### Стек
```
1. WebSocket подключение к Polymarket CLOB
   → Endpoint: wss://ws-subscriptions-clob.polymarket.com/ws/market
   → Subscribe to: all active 5m/15m BTC+ETH markets

2. Orderbook анализ в реальном времени
   → Detect: best_ask(Up) + best_ask(Down) < 1.0
   → Calculate: spread, expected profit, size available

3. Одновременный CLOB ордер на обе стороны
   → POST /order (Up) + POST /order (Down)
   → Размер: 5-24 shares per leg (избегать проскальзывания)

4. Удержание до экспирации
   → Нет sell логики нужно
   → Автоматическая выплата через Polymarket
```
